# HyperOS 4 兼容配置指南

兼容配置（Profile）让 MonoIcon 支持指定版本的 HyperOS 4 系统桌面。改配色、图标圆角或大小，在应用的「图标样式」中即可完成。

- 已有兼容配置，直接看[导入和启用](#device)。
- 更新系统或桌面后无法匹配，先看[适配范围](#compatibility)和[准备新配置](#materials)。
- 已导入但图标没有变化，按[排查与恢复](#troubleshooting)检查。

## 适配范围

| 项目 | 已记录的设备与版本 |
| --- | --- |
| 手机 | Redmi K50（22041211AC） |
| 系统 | HyperOS 4 · OS4.0.0.3.XAACNXM |
| Android | 17 |
| 系统桌面 | RELEASE-8.01.02.6144-260818-08251107-R |
| 随附配置 | [Launcher 6144 · revision 9](../app/src/main/assets/hyperos4/profiles/hyperos4-6144.json) |

这个环境已经验证配置加载、图标绘制和关闭后恢复。已目视确认 2×1 和 1×2 大图标的默认与胶囊形，以及 2×2 大图标的默认形状。2×2 圆形、平板、折叠屏和其他系统或桌面版本仍需独立验证。文件夹、应用返回动画、最近任务和通知的实测范围有限。

系统或桌面升级后，在「配置管理」重新查看匹配结果。桌面版本相同也可能需要适配新的系统版本。HyperOS 3 的 Java 桌面沿用自身的图标处理方式。

## 导入和启用

1. 在 LSPosed 启用 MonoIcon，勾选「系统桌面」和「系统界面」。给 MonoIcon 授予 Root 权限，在「主页」开启「启用模块」。
2. 在「配置管理」查看「运行环境」。支持外部 Profile 的桌面会显示「Native / Profile」。随附配置已经匹配时，保持「自动匹配」即可。
3. 使用外部配置时，先把对应手机和桌面版本的 `.json` 文件保存到「下载」。在「配置管理」点「导入 Profile」，选择该文件。如需保留现用配置，可先在对应配置卡片点「导出」。
4. 查看「HyperOS 4 Profile」选择项和「发布状态」。有多份兼容配置时，选择你要使用的一份。旧配置未声明适配系统时，会显示手动启用确认。系统更新或配置文件更换后，需要重新确认。
5. 发布完成后，在右上角电源菜单选择「重启 系统桌面」应用配置。首次启用或更新模块后，可以选择「重启作用域」，同时让系统界面加载模块。

**导入入口的位置**　已发布的 2.4.0 中，导入按钮在运行报告下方，可能需要往下滑。仓库当前源码将它移到了「运行环境」卡片下方、报告上方。[版本说明](RELEASE_NOTE.md)

<a id="large-icons"></a>

## 检查图标

导入后先观察桌面上的普通应用图标。再到「图标样式」修改配色或图标圆角，回到桌面检查效果。

- 调大图标圆角时，横向和纵向大图标的圆形端点是胶囊形。改变大图标形状后，重启桌面可刷新控件缓存。
- 想优先使用 Lawnicons 图案，在「默认图标风格」选择「Lawnicons」。若只想调整某个应用，进入「应用图标定制」。
- 日历和时钟使用静态图案。日历图案上的数字是图案的一部分。

## 排查与恢复

| 现象 | 处理方法 |
| --- | --- |
| 找不到「导入 Profile」 | 确认「运行环境」显示「Native / Profile」。使用 2.4.0 时，往下滑过运行报告。 |
| 配置显示不匹配 | 核对完整系统版本和桌面版本，向配置作者索取对应版本。在系统升级后也应重新核对。 |
| 已匹配但图标没变 | 检查 LSPosed 作用域、Root 权限和主页总开关。等发布完成后重启桌面。 |
| 桌面反复退出 | 启动保护会停用 MonoIcon 的图标处理。可以在「主页」关闭「启用模块」，或回到之前可用的配置。无法打开 MonoIcon 时，可在 LSPosed 中停用它。 |
| 需要反馈 | 在「模块设置」打开「发送日志」，选择「保存日志」。附上手机型号、完整系统和桌面版本、MonoIcon 版本、配置名称与复现步骤。 |

遇到启动保护时，选好适配配置后，在「主页」重新开启「启用模块」，再重启桌面。恢复操作需要 Root 权限。[反馈问题](https://github.com/Jerrey-liang/MonoIcon/issues)

## 为新桌面准备配置

1. 准备实际手机上的**系统桌面 APK**、设备型号、完整系统与桌面版本，以及 MonoIcon 版本。桌面 APK 应来自目标手机或能够确认版本的来源。
2. 获取 MonoIcon 源码，将源码目录和已有材料交给能读取项目并运行终端的 AI。复制任务模板，填好目标与允许的设备操作。[下载源码](https://github.com/Jerrey-liang/MonoIcon) · [AI 任务模板](Agent_example_prompt.md)
3. 要求 AI 交付候选 JSON 和验证结果，说明测试了哪台手机、哪些功能。只有离线检查时，将结果视为待上机验证的候选。每次更新系统或桌面时，用实际新版本重新核对。
