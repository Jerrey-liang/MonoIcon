# HyperOS 4 使用与兼容性

<a id="compatibility"></a>

## 适配范围

- **普通应用图标**由 MonoIcon 生成，通过 Root 写入 HyperOS 的系统主题归档。这个流程支持 Android 主用户（用户 0），实际效果取决于系统是否接受并读取归档。
- **大图标**在匹配内置支持的桌面上自动启用。当前匹配下表中的系统与桌面，同时核对 Android 版本、CPU 架构和桌面的原生组件。

| 项目 | 内置支持对应的版本 |
| --- | --- |
| 手机 | Redmi K50（22041211AC） |
| 系统 | HyperOS 4 OS4.0.0.3.XAACNXM |
| Android | 17（ARM64） |
| 系统桌面 | RELEASE-8.01.02.6144-260818-08251107-R |

上表是内置桌面扩展的匹配范围。普通应用图标的主题归档流程及各系统界面的显示效果仍需在目标设备上验证。

<a id="device"></a>

## 启用与检查

1. 在 LSPosed 启用 MonoIcon，勾选「系统桌面」和「系统界面」。打开 MonoIcon，按 Root 管理器提示授权。「启用模块」默认开启。
2. 如需让已运行的作用域加载模块，可通过右上角电源菜单重启作用域。平时更换配色、壁纸或图标样式后，普通图标会自动同步。
3. 在「运行诊断」查看「系统主题图标」的同步状态和「大图标支持」的匹配结果。

如果桌面已加载旧版 MonoIcon，升级后请重启一次作用域或手机，让桌面加载新版。

在 LSPosed 额外勾选「系统框架」，可监测系统对 MonoIcon 归档的 DRM 校验。检测到系统拒绝并移除归档后，MonoIcon 会暂停普通图标同步，在目标仍为空时恢复经校验的原备份。原主题本来没有图标归档时会保留系统默认图标。若当前已经换上其他主题，MonoIcon 会保留它。系统未提供相应校验接口时，可在「运行诊断」检查变动并恢复备份。

<a id="large-icons"></a>

横向和纵向大图标选择圆形时呈胶囊形。改变大图标形状后，重启桌面可刷新已有控件。日历和时钟使用静态图案。

<a id="troubleshooting"></a>

## 排查与恢复

| 现象 | 处理方法 |
| --- | --- |
| 普通图标未变化 | 检查 Root 授权、LSPosed 作用域和「启用模块」，再通过「刷新运行信息」检查「系统主题图标」的状态。 |
| 更换系统主题后停止同步 | 确认「启用模块」已打开，在「运行诊断」选择「在当前主题上应用 MonoIcon」。之后关闭模块时会恢复到这个主题。 |
| 系统移除了图标主题，应用仍有有效备份 | 在「运行诊断」选择「恢复原主题图标」。MonoIcon 会关闭模块并恢复备份。 |
| 大图标选项对桌面未生效 | 在「运行诊断」检查是否匹配内置支持。匹配后仍未生效时，可重启系统桌面。 |
| 想恢复图标 | 在「主页」关闭「启用模块」，保持 Root 授权并等待恢复。若已更换系统主题，MonoIcon 会保留当前主题。 |
| 桌面反复退出 | 启动保护可停用模块。遇到问题时先保存日志。要重试，在「主页」重新开启模块，再重启作用域。 |

卸载前先在 MonoIcon 内完成恢复。直接卸载可能留下仍在生效的主题归档。若已卸载，可以通过 HyperOS 的「主题」重新应用图标主题。

反馈时附上机型、完整系统版本、桌面版本、MonoIcon 版本和复现步骤。可以在「模块设置」打开「发送日志」并保存日志。 [反馈问题](https://github.com/Jerrey-liang/MonoIcon/issues) [兼容性报告模板](compatibility-report.md)

桌面扩展的配置字段和验证方式见 [技术参考](HyperOS4-profile-reference.md)。
