# HyperOS 4 Profile 适配任务模板

把下方任务卡复制给 Codex desktop、Claude Code 或 DeepSeek Harness。把 MonoIcon 源码和材料放到工具能读取的目录，未知项填「未知」。最终导入手机的是验收报告指定的候选 JSON。材料准备和导入步骤见[配置编写指南](<HyperOS4 profile编写指南.md>)。

## 复制并填写

```text
请为我这台设备的 HyperOS 4 系统桌面评估 MonoIcon 兼容配置。先阅读仓库中的
docs/Agent_example_prompt.md 和 docs/HyperOS4 profile编写指南.md，
盘点实际可读的材料和工具，再按下文完成已获授权的工作。请用中文交付。

源码目录及版本或 commit：
目标桌面 APK，或 libapp.so 与 libapp_launcher.so 的路径：
材料和输出目录：
设备型号及形态（手机／平板／折叠屏）：
系统完整版本、Android 版本／SDK、ABI：
桌面包名、versionCode、versionName：
APK 来源和采集时间：
MonoIcon 与 LSPosed 版本：
运行环境截图、日志或此前报告（可选）：
现象及要验收的功能：
是否包含 2×1／1×2／2×2 大图标：

允许的电脑操作（如读取所给材料、离线核对、生成候选和运行本机检查，空白为无）：
允许的手机操作（如读取设备信息、导入、切换设置、重启作用域，逐项填写，空白为无）：
允许修改的项目文件（空白为无）：
```

工具无法直接读取文件时，把下文一并粘贴。离线操作依赖实际文件和终端，缺少这些条件时，在报告中标出待执行的检查。

## 离线交付与验收

1. 记录源码版本、已有改动、输入来源及 SHA-256，保留原件，在新目录工作。依据设备记录核对系统与桌面身份。当前原生配置适用于 arm64、无 Java 代码的 `com.miui.home` 单 APK。只有 ELF 时，把 APK 信息标为未知。
2. 读取当前仓库的官方 `hyperos4-6144`、解析器和配置加载代码。官方配置属于特定构建和系统，按当前源码核对版本及匹配规则。身份比较可使用 `tools/launcher_inspector.py`，匹配结论只覆盖比较所用材料。具体历史验收范围见[兼容性记录](<HyperOS4 profile编写指南.md#compatibility>)。
3. 证据足够时，输出使用独立 ID 的无 BOM UTF-8 JSON，并保存可复现的生成记录。保持目标版本和系统的精确匹配。把每项功能对应的原始依据、行为和恢复方式写进报告。必需项缺少证据或需要引擎变更时，交付缺口和下一步。可选项缺少证据时，记录保留系统行为。
4. 分别记录真实 C++ `Parse`、`tools/verify_hyperos4_profile.py` 的二进制核对和实际功能语义复核。主机 `tools/run_profile_tests.py` 只回归官方 6144。每项注明输入、命令、结果与证据范围，未运行就标「未执行」。
5. 交付实际文件路径。报告 `PROFILE_REPORT.md` 写明环境、候选摘要、功能覆盖、验证结果和待办。候选 JSON、生成记录和检查日志放到任务卡指定的目录。截图、日志和二进制原件保存在本地。

## 手机验收

- 仅执行任务卡已授权的操作。先记录候选摘要、设备环境、LSPosed 作用域和回退方式。导入可能触发配置选择与发布。选择配置后按提示重启作用域，用本次进程状态及实际桌面画面确认效果。
- 2.4.0 发布版在「配置管理」的诊断列表后提供「导入 Profile」。从源码提交 `0f715e0` 起，入口位于「运行环境」卡片下、诊断列表前。该入口仅在运行环境识别为 `Native / Profile` 时显示。
- 在 2.4.0 用主页「启用模块」验证停用和恢复。在「图标样式」验证配色、图标圆角和「默认图标风格」（含 Lawnicons），以及「应用图标定制」的覆盖与恢复。按任务目标检查桌面启动、普通图标、缺资源回退、文件夹、静态日历／时钟、返回动画和大图标，并记录未测场景。
- 遇到问题时保存日志，关闭主页「启用模块」或恢复先前已验证的配置，然后按应用提示操作。交付时写明是只完成材料核对、得到离线候选，还是通过了指定手机场景。
